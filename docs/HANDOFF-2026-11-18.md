## Architecture

`navigation/saved_map.launch.py` launches:

1. YDLidar X2 and static base-to-laser transform (existing 0,0,0.1 m assumption).
2. Cartographer pure localization using the frozen PBStream and a small live
   submap window. It supplies map→odom→base_link; no AMCL is running.
3. Nav2 map_server serving the saved YAML/PGM. No live occupancy publisher is
   used, so localization does not overwrite the static navigation image.
4. `tf_odometry.py`, deriving velocities from odom→base_link TF. This is
   lidar-derived odometry, not verified wheel feedback.
5. Nav2 planner/controller/BT servers, costmaps, and velocity smoothing.
   Unknown cells are not traversable. The custom BT plans/follows paths without
   automatic backup/spin recovery behaviors.
6. `motor_gate.py`, dry-run by default. Hardware mode requires complete robot
   settings, an explicit localization confirmation, and arming. It checks
   command, lidar and TF freshness and nearby obstacles independently of ROS
   callbacks. Right-wheel inversion matches the confirmed manual controls.
7. `api.py` on loopback port 18766 for status/map, path plans, destinations,
   localization initialization/confirmation, arming, navigation and cancel.

The provisional planning radius is 0.35 m, **not a measured robot dimension**.
The user has not supplied width, length, wheel-centre separation or measured
speed. Missing fields deliberately prevent a hardware-enabled launch.
Autonomous requested velocity is provisionally limited to 0.15 m/s and 0.3 rad/s.
Those are requested software limits, not verified physical speed limits.
